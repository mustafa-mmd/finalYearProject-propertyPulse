# 12. Property Approval and Verification Workflow

A newly submitted property must not immediately appear publicly.

Design the following workflow:

1. The owner, landlord, or agent creates a property.
2. The listing is saved as `DRAFT`.
3. The user completes all required fields.
4. The system calculates a listing-completeness score.
5. The user submits the listing for verification.
6. The status becomes `PENDING_VERIFICATION`.
7. Automated validation begins.
8. Google Gemini analyzes the listing data, images, and documents.
9. Rule-based fraud checks run.
10. Duplicate-listing checks run.
11. Image-quality and image-consistency checks run.
12. Location and address checks run.
13. Owner, agent, or agency verification is checked.
14. The system generates a risk score.
15. A verification administrator reviews the listing.
16. The administrator approves, rejects, or requests changes.
17. Only an approved listing becomes publicly visible.

Recommended listing statuses:

* `DRAFT`
* `INCOMPLETE`
* `PENDING_SUBMISSION`
* `PENDING_AI_REVIEW`
* `PENDING_MANUAL_REVIEW`
* `CHANGES_REQUESTED`
* `APPROVED`
* `PUBLISHED`
* `REJECTED`
* `SUSPENDED`
* `FLAGGED`
* `EXPIRED`
* `ARCHIVED`
* `RENTED`
* `SOLD`

Define valid status transitions and prevent users from bypassing the verification process.
